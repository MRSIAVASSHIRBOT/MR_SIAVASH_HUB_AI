# NEXUS Read-only Static Analysis

The initial NEXUS analysis module inventories Python source files and uses the Python AST to flag selected risky patterns. It never imports or executes target modules and returns only file/line/rule evidence, not source excerpts.

The rule set is intentionally narrow and advisory. It detects dynamic evaluation, pickle deserialization, unsafe YAML loading, subprocess calls with `shell=True`, `os.system`/`os.popen`, and Requests and HTTPX calls or client constructors that explicitly set `verify=False`, including directly chained calls and straightforward local client instances whose `verify` attribute is set to `False` or whose request method passes `verify=False`. Instance tracking is a deliberately limited AST heuristic, not complete interprocedural data-flow analysis. Findings require human review; absence of findings is not proof of security. Generated directories and symlinks are skipped, and file count and size are bounded. Repository writes and patch application are outside this initial read-only scope.
